Database already created (do not create a second one):

- Name: `greeninstallatie`
- ID: `f0728db7-edb9-438c-9a64-5d04ee828137`

Wrangler binds it as `DB` in `wrangler.toml`.

## Inspect D1

List tables locally:

```bash
npx wrangler d1 execute greeninstallatie --local --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;"
```

Remote (production binding; requires Cloudflare login):

```bash
npx wrangler d1 execute greeninstallatie --remote --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;"
```

Inspect a table (example):

```bash
npx wrangler d1 execute greeninstallatie --local --command "PRAGMA table_info(appointments);"
npx wrangler d1 execute greeninstallatie --local --command "SELECT id, status, appointment_date FROM appointments LIMIT 20;"
```

## Create a migration

1. Add a new file under `migrations/` with the next number: `0002_short_name.sql`.
2. Use `CREATE TABLE IF NOT EXISTS`, `ALTER TABLE … ADD COLUMN`, or `CREATE INDEX IF NOT EXISTS`.
3. Never `DROP` tables unless the product owner explicitly asks.
4. Commit the SQL. Do not paste one-off schema changes only in the dashboard.

## Apply local migrations

```bash
npm run db:migrate:local
```

Equivalent:

```bash
npx wrangler d1 migrations apply greeninstallatie --local
```

Local SQLite files live under `.wrangler/` (gitignored).

## Apply production migrations

Only after reviewing the SQL:

```bash
npm run db:migrate:remote
```

Equivalent:

```bash
npx wrangler d1 migrations apply greeninstallatie --remote
```

This was **not** run as part of the foundation work. Apply it from a machine logged into the correct Cloudflare account.

For a named Wrangler environment:

```bash
npx wrangler d1 migrations apply greeninstallatie --remote --env production
```

## Safely modify the schema

- Prefer additive changes.
- Backfill new columns in a second, explicit step if needed.
- Rebuild indexes with `CREATE INDEX IF NOT EXISTS`.
- Partial unique index `idx_appointments_active_slot` blocks two non-cancelled bookings on the same date+time.

## Rollback / recovery

D1 migrations are forward-only in this repo. There is no automatic down migration.

Recovery options:

1. Add a new migration that reverses a safe change (for example drop a newly added unused column only if instructed).
2. Restore from a D1 backup/export taken before the change (Cloudflare dashboard / `wrangler d1 export`).
3. Do not `DROP TABLE` to “start over” on production.

Export example (manual, when needed):

```bash
npx wrangler d1 export greeninstallatie --remote --output backup.sql
```
